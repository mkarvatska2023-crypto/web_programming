# Лабораторна робота №7: Завантаження даних з публічного API та відображення на сторінці

**Проєкт:** Акустична варта  
**Дисципліна:** WEB-програмування

## Мета роботи
Навчитися отримувати дані у форматі JSON із зовнішнього REST API за допомогою HTTP `GET`-запиту через `fetch()` та `async/await`, перевіряти об'єкт `Response` (`response.ok`, `response.status`), перетворювати відповідь у масив об'єктів JavaScript (`response.json()`) і динамічно формувати картки сенсорів у DOM.

## Підготовка даних у MockAPI
1. Створено проєкт у [MockAPI](https://mockapi.io/projects) та налаштовано префікс `/api/v1`.
2. Створено ресурс `sensors` з endpoint-ом:
   `https://YOUR_PROJECT.mockapi.io/api/v1/sensors`
3. Задано структуру об'єкта сенсора з полями:
   - `id` — ідентифікатор запису;
   - `name` — назва сенсора (наприклад, `"Сенсор Центр"`);
   - `district` — район міста (наприклад, `"Галицький"`);
   - `noiseLevel` — рівень шуму в дБ (числове значення, наприклад, `72`);
   - `status` — статус роботи (`"active"` або `"inactive"`).
4. Додано тестові записи сенсорів та перевірено відповідь JSON безпосередньо в браузері за адресою endpoint-у.

## Реалізація у проєкті
- **Захардкоджений масив сенсорів прибрано** з JavaScript-коду — джерелом даних є відповідь REST API.
- **Контейнер у DOM:** на сторінці використано блок `<div id="sensors-list" class="sensors__list"></div>`, до якого додаються згенеровані картки.
- **Завантаження даних (`loadSensors()`):** асинхронна функція виконує запит `await fetch(API_URL)`, перевіряє `response.ok` (викидаючи помилку `HTTP error: ${response.status}` у разі неуспішного статусу), зчитує JSON через `await response.json()` і передає масив у функцію відображення.
- **Відображення карток (`renderSensors(sensors)`):** очищає контейнер `#sensors-list`, перебирає масив через `forEach()`, створює елементи `<article class="sensor-card">` через `document.createElement()` та виводить назву, район, рівень шуму і статус кожного сенсора.
- **Обробка помилок:** завантаження обгорнуто в блок `try / catch` для перехоплення мережевих збоїв, помилок HTTP та помилок у коді з виведенням інформації в консоль та/або контейнер сторінки.

## Перевірка роботи
1. Під час відкриття сторінки автоматично викликається `loadSensors()` та виконується `GET`-запит на `/api/v1/sensors`.
2. У **DevTools → Network** зафіксовано успішний запит зі статусом `200` та отриманий JSON-масив.
3. На сторінці коректно відображаються картки всіх сенсорів з актуальними даними після оновлення сторінки чи змін у MockAPI.
## Висновки
Під час виконання лабораторної роботи №7 для проєкту **«Акустична варта»** було реалізовано завантаження даних про сенсори із зовнішнього REST API замість використання статичного масиву в JavaScript-коді.

Було розгорнуто тестовий ресурс `sensors` у [MockAPI](https://mockapi.io/projects) з префіксом `/api/v1` та структурою об'єкта сенсора (`id`, `name`, `district`, `noiseLevel`, `status`), перевірено роботу endpoint-у `GET /api/v1/sensors` у браузері та в **DevTools → Network**. У клієнтському коді за допомогою `async/await` і `fetch()` налагоджено отримання об'єкта `Response`, перевірку статусу відповіді (`response.ok`, `response.status`), перетворення JSON у масив JavaScript через `response.json()`, динамічне створення карток у контейнері `#sensors-list` через функцію `renderSensors(sensors)` та базову обробку помилок у блоці `try / catch`.

Отримані навички дозволяють відокремлювати дані від інтерфейсу, працювати з асинхронними мережевими запитами та оновлювати вміст вебсторінки на основі актуальних даних із сервера.
